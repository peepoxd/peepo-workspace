🏗️ ARCHITECTURE OVERVIEW
│
├─ 📦 1. PLUGIN SYSTEM (หัวใจหลัก)
│  │
│  ├─ ทุกความสามารถขยายผ่าน Plugin
│  ├─ Plugin ประกอบด้วย:
│  │  ├─ Commands (คำสั่ง /slash)
│  │  ├─ Agents (AI ผู้เชี่ยวชาญ)
│  │  ├─ Skills (ความสามารถพิเศษ)
│  │  ├─ Hooks (Event triggers)
│  │  └─ MCP Servers (External tools)
│  │
│  └─ โครงสร้าง Plugin:
│     │
│     │  plugin-name/
│     │  ├── .claude-plugin/
│     │  │   └── plugin.json        # Metadata (ชื่อ, version, author)
│     │  ├── commands/              # Slash commands (*.md)
│     │  ├── agents/                # AI agents (*.md)
│     │  ├── skills/                # Skills (*.md)
│     │  ├── hooks/
│     │  │   ├── hooks.json         # Hook configuration
│     │  │   └── hooks-handlers/    # Handler scripts
│     │  └── .mcp.json              # MCP server config
│
├─ 🎮 2. COMMANDS (คำสั่ง)
│  │
│  ├─ Slash commands เช่น /commit, /code-review
│  ├─ เขียนเป็น Markdown + YAML frontmatter
│  ├─ กำหนด allowed-tools (security)
│  ├─ Dynamic context injection ด้วย !`backticks`
│  │
│  └─ ตัวอย่าง:
│     │
│     │  ---
│     │  allowed-tools: Bash(git:*), Read, Write
│     │  description: Create a git commit
│     │  ---
│     │
│     │  ## Context
│     │  - Git status: !`git status`
│     │
│     │  ## Your task
│     │  Create a commit based on changes.
│
├─ 🤖 3. AGENTS (AI ผู้เชี่ยวชาญ)
│  │
│  ├─ Specialized AI สำหรับงานเฉพาะทาง
│  ├─ เลือก Model ได้ (opus, sonnet, haiku)
│  ├─ Parallel execution (หลาย agent พร้อมกัน)
│  ├─ Confidence scoring (0-100)
│  │
│  ├─ ตัวอย่าง Agent:
│  │  ├─ code-reviewer — ตรวจ code quality
│  │  ├─ code-explorer — วิเคราะห์ codebase
│  │  ├─ code-architect — ออกแบบ architecture
│  │  └─ plugin-validator — ตรวจสอบ plugin
│  │
│  └─ โครงสร้าง Agent:
│     │
│     │  ---
│     │  name: code-reviewer
│     │  model: opus
│     │  color: green
│     │  ---
│     │
│     │  You are an expert code reviewer...
│
├─ 🎯 4. SKILLS (ความสามารถพิเศษ)
│  │
│  ├─ Reusable AI-powered modules
│  ├─ ความรู้เฉพาะทาง (domain knowledge)
│  ├─ Auto-invoke ตาม context
│  │
│  ├─ ตัวอย่าง Skills:
│  │  ├─ frontend-design — UI/UX guidance
│  │  ├─ hook-development — สร้าง hooks
│  │  ├─ mcp-integration — เชื่อมต่อ external tools
│  │  └─ plugin-settings — จัดการ config
│  │
│  └─ โครงสร้าง Skill:
│     │
│     │  ---
│     │  name: skill-name
│     │  description: When to invoke this skill
│     │  ---
│     │
│     │  [Comprehensive guidance...]
│
├─ 🪝 5. HOOKS (Event Triggers)
│  │
│  ├─ Event-driven automation
│  ├─ ทำงานที่ lifecycle points ต่างๆ
│  │
│  ├─ Hook Events:
│  │  │
│  │  │  ┌─────────────────┬──────────────────────────────────┐
│  │  │  │ Event           │ เมื่อไหร่                         │
│  │  │  ├─────────────────┼──────────────────────────────────┤
│  │  │  │ SessionStart    │ เริ่ม session                    │
│  │  │  │ SessionEnd      │ จบ session                       │
│  │  │  │ PreToolUse      │ ก่อนใช้ tool (validate)          │
│  │  │  │ PostToolUse     │ หลังใช้ tool (react)             │
│  │  │  │ Stop            │ Agent เสร็จงาน                   │
│  │  │  │ UserPromptSubmit│ User พิมพ์คำสั่ง                 │
│  │  │  └─────────────────┴──────────────────────────────────┘
│  │
│  ├─ Hook Types:
│  │  ├─ Prompt-Based (LLM reasoning)
│  │  └─ Command-Based (bash/python script)
│  │
│  └─ ตัวอย่าง:
│     │
│     │  {
│     │    "hooks": {
│     │      "PreToolUse": [{
│     │        "matcher": "Bash",
│     │        "hooks": [{
│     │          "type": "command",
│     │          "command": "python validate.py"
│     │        }]
│     │      }]
│     │    }
│     │  }
│
└─ 🔌 6. MCP (Model Context Protocol)
   │
   ├─ เชื่อมต่อ External Services
   ├─ Standard protocol สำหรับ LLM tools
   │
   ├─ Transport Types:
   │  ├─ stdio — Local process
   │  ├─ HTTP — REST API
   │  └─ SSE — Server-Sent Events
   │
   └─ ตัวอย่าง:
      │
      │  {
      │    "database-server": {
      │      "command": "./servers/db-server",
      │      "args": ["--config", "config.json"]
      │    }
      │  }

🔄 DATA FLOW (Session Lifecycle)
│
│  ┌─────────────────┐
│  │  SessionStart   │ ← Hooks: Initialize context
│  └────────┬────────┘
│           ▼
│  ┌─────────────────┐
│  │   User Input    │ ← UserPromptSubmit hook
│  └────────┬────────┘
│           ▼
│  ┌─────────────────┐
│  │  Tool Planning  │ ← AI decides which tools
│  └────────┬────────┘
│           ▼
│  ┌─────────────────┐
│  │  PreToolUse     │ ← Validate before execution
│  └────────┬────────┘
│           ▼
│  ┌─────────────────┐
│  │ Tool Execution  │ ← Bash, Read, Write, etc.
│  └────────┬────────┘
│           ▼
│  ┌─────────────────┐
│  │  PostToolUse    │ ← React to results
│  └────────┬────────┘
│           ▼
│  ┌─────────────────┐
│  │    Response     │ ← Generate output
│  └────────┬────────┘
│           ▼
│  ┌─────────────────┐
│  │   Stop Hook     │ ← Verify completion
│  └────────┬────────┘
│           ▼
│  ┌─────────────────┐
│  │   SessionEnd    │ ← Cleanup
│  └─────────────────┘

🔐 SECURITY MODEL
│
├─ Permission System
│  │
│  ├─ allowed-tools — Whitelist เครื่องมือที่ใช้ได้
│  │  ├─ Bash(git:*) — เฉพาะ git commands
│  │  ├─ Bash(*) — ทุก bash command
│  │  ├─ Read, Write — File operations
│  │  └─ Tool(*) — ทุก tool
│  │
│  ├─ Hook Validation
│  │  ├─ PreToolUse — ตรวจก่อนรัน
│  │  └─ Exit codes: 0=pass, 1=warn, 2=block
│  │
│  └─ Security Patterns (ตรวจจับ)
│     ├─ Command injection
│     ├─ dangerouslySetInnerHTML (XSS)
│     ├─ GitHub Actions vulnerabilities
│     └─ Sensitive file access
│
└─ Best Practices
   ├─ ไม่ commit secrets (.env)
   ├─ ไม่ใช้ --force flags
   └─ Review ก่อน merge
