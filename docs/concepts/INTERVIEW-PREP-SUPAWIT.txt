│  │  └─────────────────────────────────────────────────────┘

│     ├─ GFMIS → ระบบบริหารการเงินการคลังภาครัฐ

   │  └─────────────────────────────────────────────────────┘

📊 MODULES (โมดูลหลัก)
│
├─ ระบบ สสส. (8 Modules)
│  │
│  ├─ 1. ข้อเสนอโครงการ    → สร้าง/แก้ไข/ยื่น, แนบไฟล์, งบประมาณ
│  ├─ 2. คัดกรอง/กลั่นกรอง  → ตรวจคุณสมบัติ, ความเห็น, กำหนดงวด
│  ├─ 3. อนุมัติโครงการ     → พิจารณา, บันทึกเงื่อนไข
│  ├─ 4. สัญญา            → ตรวจเอกสาร, ลงนามอิเล็กทรอนิกส์
│  ├─ 5. เบิกจ่าย/ส่งงาน    → ขอเบิกงวด, รายงาน, หลักฐาน
│  ├─ 6. ปิดโครงการ        → รายงานสรุป, ตรวจครุภัณฑ์
│  ├─ 7. Dashboard/KPI    → สถานะ, งบประมาณ, แจ้งเตือน
│  └─ 8. รายงาน           → Export Excel/PDF, สถิติ
│
└─ ระบบ PCS (7 Modules)
   │
   ├─ 1. Sales      → Import Order, Delivery Note, Invoice
   ├─ 2. MRP        → คำนวณความต้องการผลิต+วัตถุดิบอัตโนมัติ
   ├─ 3. Production → Production Plan, Work Order, Tag
   ├─ 4. Purchase   → PR, PO, Receive Material
   ├─ 5. Inventory  → Stock IN/OUT, Warehouse, Barcode Scan
   ├─ 6. Shipment   → Delivery, Shipment Tag, Tracking
   └─ 7. Dashboard  → Real-time Status, KPI, Alert

❓ INTERVIEW QUESTIONS (16 ข้อ)
│
├─ 🔧 Technical Questions (Q1-Q5)
│  │
│  ├─ Q1: ทำไมเลือก PostgreSQL?
│  │  └─ A: Open-source, ACID compliance, JSON support, Full-text search
│  │
│  ├─ Q2: ทำไมใช้ Agile?
│  │  └─ A: Stakeholders หลายกลุ่ม, ต้องการ feedback เร็ว, ส่ง MVP ก่อนได้
│  │
│  ├─ Q3: MRP คืออะไร?
│  │  └─ A: Material Requirements Planning - คำนวณความต้องการวัตถุดิบ
│  │        จาก Sales Order + BOM + Stock + Lead Time
│  │
│  ├─ Q4: ระบบ สสส. เชื่อมต่อระบบภาครัฐอะไร?
│  │  └─ A: GFMIS (การเงิน), e-GP (จัดซื้อจัดจ้าง), SSO (Authentication)
│  │
│  └─ Q5: ทำไม PCS ต้องมี Offline Mode?
│     └─ A: Handy Scanner ใช้ในโรงงาน, Production ต้องไม่หยุด
│
├─ 🔄 Process Questions (Q6-Q9)
│  │
│  ├─ Q6: Workflow เบิกจ่าย สสส.?
│  │  └─ A: ภาคีขอเบิก → นักวิชาการตรวจ → ผู้อนุมัติพิจารณา → GFMIS
│  │
│  ├─ Q7: Production Workflow PCS?
│  │  └─ A: Order → MRP → PR/PO → Production (Handy) → Stock OUT → Ship
│  │
│  ├─ Q8: Bug ใน Production handle อย่างไร?
│  │  └─ A: Target ≤5 bugs/Sprint, Weekly review, Priority: Security first
│  │
│  └─ Q9: User Adoption ต่ำ แก้อย่างไร?
│     └─ A: Training, Super User, UI/UX ง่าย, Mobile responsive
│
├─ 🏛️ Architecture Questions (Q10-Q13)
│  │
│  ├─ Q10: ทำไมแยก 5 Layer?
│  │  └─ A: Separation of Concerns, Scalability, Security, Testability
│  │
│  ├─ Q11: Redis ใช้ทำอะไรใน PCS?
│  │  └─ A: Session cache, MRP cache, Real-time dashboard, Queue
│  │
│  ├─ Q12: ทำไมต้องลงนามอิเล็กทรอนิกส์?
│  │  └─ A: ผลทางกฎหมาย, ลดกระดาษ 80%, Audit trail, Remote work
│  │
│  └─ Q13: Data Entity Relationships?
│     └─ A: Project 1:N Milestone/Payment/Document, N:M User, 1:1 Contract
│
└─ 💬 Behavioral Questions (Q14-Q16)
   │
   ├─ Q14: ความท้าทายที่สุด?
   │  ├─ สสส.: Integration กับ GFMIS (ระบบภาครัฐ, ต้อง PoC + Parallel Run)
   │  └─ PCS: MRP accuracy (ต้อง tune parameter, review ทุกสัปดาห์)
   │
   ├─ Q15: ถ้าทำใหม่จะทำอะไรต่าง?
   │  └─ A: Training เร็วขึ้น, Integration testing ตั้งแต่ต้น, Feature flags
   │
   └─ Q16: ทำงานกับ stakeholders หลายกลุ่ม?
      └─ A: Sprint Review ร่วมกัน, Workshop แยก role, PO เป็นตัวกลาง
