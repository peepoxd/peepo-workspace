  1. ภาพรวม Architecture
═══════════════════════════════════════════════════════════════════════

  โปรเจคนี้ใช้ Clean Architecture แบ่งเป็น 4 layers:

  ┌─────────────────────────────────────────────────────────────────┐
  │                                                                 │
  │   presentation       ← รับ request จาก client                  │
  │        │                                                        │
  │        ▼                                                        │
  │   application         ← business logic, DTO, validation        │
  │        │                                                        │
  │        ▼                                                        │
  │   domain              ← entities, enums, repository interfaces │
  │        │                                                        │
  │        ▼                                                        │
  │   infrastructure      ← JWT, database, email, cache           │
  │                                                                 │
  └─────────────────────────────────────────────────────────────────┘

  กฎ: layer ด้านบนเรียก layer ด้านล่างได้
      layer ด้านล่างห้ามเรียก layer ด้านบน
      domain ไม่พึ่งพา framework ใดๆ (ยกเว้น JPA annotations)

  2. Request Flow (เส้นทางข้อมูล)
═══════════════════════════════════════════════════════════════════════

  ตัวอย่าง: POST /api/v1/auth/register

  Client
    │
    │  POST { name, email, password }
    ▼
  ┌──────────────────┐
  │  JwtAuthFilter   │  ← เช็ค Authorization header (ไม่มี = ผ่านได้เพราะ /auth/**)
  └──────────────────┘
    │
    ▼
  ┌──────────────────┐
  │  SecurityConfig  │  ← /api/v1/auth/** = permitAll
  └──────────────────┘
    │
    ▼
  ┌──────────────────┐
  │ AuthController   │  ← รับ @RequestBody, @Valid → validate input
  └──────────────────┘
    │  เรียก authService.register(request)
    ▼
  ┌──────────────────┐
  │  AuthService     │  ← business logic:
  │                  │     1. เช็ค email ซ้ำไหม
  │                  │     2. hash password (BCrypt)
  │                  │     3. save user
  │                  │     4. สร้าง JWT access + refresh token
  └──────────────────┘
    │  ใช้ UserRepository, JwtTokenProvider, PasswordEncoder
    ▼
  ┌──────────────────┐
  │  UserRepository  │  ← Spring Data JPA → PostgreSQL
  └──────────────────┘
    │
    ▼
  Client ← { accessToken, refreshToken, user: { id, name, email, role } }


  ถ้าเกิด error:

  Exception ─── throw ───▶ GlobalExceptionHandler
                              │
                              ├── ResourceNotFoundException → 404
                              ├── BusinessException → 401/409/400
                              ├── ValidationException → 400
                              └── Exception (อื่นๆ) → 500
                              │
                              ▼
                           ApiResponse { success: false, error: { code, message } }

  4. Layer-by-Layer อธิบาย
═══════════════════════════════════════════════════════════════════════

  ┌─────────────────────────────────────────────────────────────────┐
  │                                                                 │
  │  LAYER          ทำอะไร           ห้ามทำอะไร                     │
  │  ─────          ──────           ──────────                     │
  │  presentation   รับ/ส่ง HTTP     ห้ามมี business logic          │
  │  application    business logic   ห้ามรู้จัก HTTP, SQL           │
  │  domain         entities, enums  ห้ามรู้จัก framework           │
  │  infrastructure DB, JWT, Email   ห้ามมี business logic          │
  │  config         ตั้งค่า Spring    ห้ามมี logic ใดๆ               │
  │                                                                 │
  └─────────────────────────────────────────────────────────────────┘

  ทำไมแบ่งแบบนี้?

  1. Testable   → test AuthService โดยไม่ต้องมี HTTP server
  2. Swappable  → เปลี่ยน PostgreSQL เป็น MongoDB แก้แค่ infrastructure
  3. Readable   → อ่าน controller รู้ว่ามี API อะไร
                   อ่าน service รู้ว่า logic ทำอะไร
                   อ่าน domain รู้ว่า data หน้าตาเป็นยังไง

  5. วิธี Run โปรเจค
═══════════════════════════════════════════════════════════════════════

  วิธีที่ 1: Docker Compose (แนะนำ)
  ─────────────────────────────────
  docker compose up -d          # start postgres + redis + app
  docker compose logs -f app    # ดู log
  docker compose down           # หยุด

  วิธีที่ 2: Local Development
  ─────────────────────────────
  # ต้อง start postgres + redis ก่อน
  docker compose up -d postgres redis

  # แล้ว run app
  mvn spring-boot:run

  วิธีที่ 3: Build JAR
  ─────────────────────
  mvn clean package -DskipTests
  java -jar target/task-management-api-0.1.0.jar

  วิธี Test:
  ──────────
  mvn test                       # ใช้ H2 in-memory ไม่ต้อง Docker
